# VS Code 内容加载优化

本轮只调整搜索、请求超时、审批数据复用和刷新展示，不改变本地 Git 操作流程或 Web 链路。

- **GitHub 搜索兼容**：支持与现有调用方一致的 `^` 前缀、`$` 后缀和普通关键词匹配，内部文字按字面值比较。分页过滤无匹配项时保留下一页状态，避免提前停止。例如 `^feature/v1/` 不再把 `^` 当作分支名称字符，也不会匹配 `feature/v10/`。
- **超时与取消**：GitLab HTTP 请求默认 20 秒超时，已有显式超时仍优先。切换平台、实例、API 地址、凭据或工作区时，取消工厂创建的旧连接上的只读 HTTP 请求。写请求不接入此取消信号，也不自动重试；超时后的远程结果仍需按原有流程核对。
- **审批请求复用**：待办和状态栏通过同一平台工厂复用当前用户、待审批 MR 列表、个人批准状态的在途请求及 5 秒内的成功结果。缓存按平台、网页/API 地址和凭据摘要隔离；返回独立副本，查询失败不缓存。审批、合并、创建、删除等工厂服务写操作在开始和结束时清空关联缓存。MR 详情、Diff 及写操作前的版本校验不使用这层缓存。
- **保留旧内容**：同一连接刷新待办或总览时保留已有列表；更新期间标记旧数据，失败后保留并展示提示和更新时间。待办刷新期间及失败后禁止从旧项发起审批、合并或 conflict 操作，成功刷新后恢复。连接/凭据/工作区切换仍清空旧内容，避免混淆账号或仓库。尚未首次加载成功时继续显示加载或错误提示。

状态栏仍默认每 60 秒查询，不会因轮询清空正在查看的待办 Diff。5 秒缓存期内的读取可能复用最近结果；外部新增或批准的 MR 会在后续刷新中更新。

验证包括模拟 API 的请求数量、凭据隔离、写后失效、失败重试、分页搜索、旧内容保留，以及本机 HTTP 服务的实际超时和取消测试。运行 `pnpm --dir apps/vscode test:loading`。
