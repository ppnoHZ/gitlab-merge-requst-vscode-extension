# IDEA 分支管理使用指南

1. 打开 View → Tool Windows → GitLab Workbench，配置 GitLab 连接及 Token。
2. 进入“分支管理”，输入关键词并搜索。分支按 `/` 逐层展开，默认包含 conflict；取消“仅常用分支”可显示全部结果。
3. 加载完成后后台检查 main，真实分支叶节点显示“已合入 main”“未合入 main”或“main 状态未知”。目录不显示状态，未知时可刷新重试。
4. 选中已合入的分支，点击“删除已合入分支”并确认。插件重新核对保护状态、分支 SHA 和 main SHA；默认分支、main、受保护分支及状态未知的分支禁止删除。本地分支保留。
5. 删除请求失败时先刷新或打开 GitLab 核实，避免重复操作。

检查基于提交祖先关系，squash/rebase 后仅代码相同的分支可能显示未合入，暂不支持据此删除。GitLab 删除接口不提供 SHA 条件删除，最终检查和删除之间存在并发窗口，操作期间应避免其他人推送。

选中分支还可复制完整名称、打开 GitLab 页面、创建 release/hotfix、检查 release 同版本 feature/MR，以及预览实际差异后创建 MR。详细连接及 Conflict 操作参见 README.md。

## 筛选、模板与安全开关

- “仅常用分支”和 main 状态筛选按项目保存，重启后保留。不同筛选条件取交集。
- “分支设置”可配置 release/hotfix 名称模板。支持 `{version}`、`{issue}`、`{description}`、`{descriptionSuffix}`；保存和创建时检查名称合法性。
- 远程删除默认关闭，在“分支设置”明确填写 true 后才显示合规分支的删除入口。
- 从分支创建 MR 时只展示符合 Source 类型的目标，同版本 release 优先。没有目标时清空搜索并重新加载。

尚未完全对齐 VS Code：main 判断仍为保守祖先关系；更新时间筛选、任意常用目录组合、工单链接、可配置 conflict 模板和 Rebase 入口仍待实现。

## 快捷交互

分支工具区分为两列，窄侧栏下可直接访问操作。刷新和 main 状态更新后保留仍存在的目录展开状态与分支选择。右键真实分支可检查、创建 MR、复制完整名称；满足条件且开启删除开关时提供删除入口。双击真实分支直接检查，双击目录仍为展开/折叠。底部显示所选分支完整路径；所有分页自动加载，不再展示无效的“加载更多”按钮。后台操作时右键菜单禁用，避免重复提交。

## 线上数据来源

工作台的项目、分支、Tag、最新提交作者/时间/标题、MR、审批、比较差异、main 祖先关系及删除前检查均直接访问 GitLab API。无需本地克隆或 fetch；可在连接设置填写远程实例和项目路径。Git Remote 仅用于首次自动填充连接，不作为分支或合入状态的数据来源。树节点展示远程最新提交作者与时间，悬停显示完整 SHA 和提交标题，字段缺失时不使用本地数据补齐。

本地解决冲突、提交、推送仍交给 IDEA Git 工具；未推送的本地改动不会出现在工作台远程结果中。main 的 squash/rebase 内容等价判断仍未实现，不会回退到本地 Git 或将未知状态当作已合入。

## VS Code 风格布局

工作台采用纵向可折叠分区，同时展示“分支管理”和“我的待办”，点击分区标题展开或折叠。连接设置保留在顶部；新建分支位于分支管理区，先选择类型；待办刷新位于待办区。分支操作使用节点右键菜单或分支区按钮，刷新保留树的展开与选择。界面颜色和字体跟随 IDEA 主题。

本次只对齐已实现分区的布局，不添加无法使用的上线总览或操作审计占位区。线上基线选择和逐步表单仍为后续交互差异，当前创建窗口仍需输入基线名称。

## IDEA 原生交互

- 顶部连接、刷新和分支常用操作使用 IntelliJ Action Toolbar；后台操作时动作会自动禁用，未选择真实分支时检查、创建 MR、复制和打开操作不可用。
- 分支采用 IntelliJ `Tree`，空数据时显示操作提示。MR 待办使用 `JBList`，空列表会明确显示当前没有待办；双击 MR 或选中后按 Enter 可在浏览器打开。
- 搜索框、分支树、状态筛选、MR 列表和连接字段提供可访问名称，支持键盘焦点及屏幕阅读器识别。组件间距、表单标签和边距使用 IntelliJ 平台规范并跟随 IDE 主题。
- 连接窗口使用标准标签表单。Token 仍保存到 PasswordSafe，测试连接在后台执行，失败保留输入。
- 第一次成功加载只建立待审批基线，不弹通知。此后轮询发现新增的待审批 MR 时，IDE 右下角显示通知；刷新失败或审批状态未确认时不会误报。

## IDEA 版本兼容

插件最低支持 IntelliJ Platform 243，不设置最高版本限制，因此新版本 IDEA 不会仅因 `until-build` 被拒绝安装。构建可用 `-PideaVersion=<版本>` 指定 SDK；GitHub Actions 每次读取 JetBrains 官方最新稳定版执行构建，并在每周一定时复验。

JetBrains 未来仍可能调整或移除 API。定时验证用于尽早发现这种变化，不能保证旧插件包在所有未来版本中永远正常；CI 失败后需要发布修复版本。其他 JetBrains IDE 产品需分别验证。
